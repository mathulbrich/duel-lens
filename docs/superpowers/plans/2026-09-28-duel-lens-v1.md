# Duel Lens v1 Implementation Plan

> **Historical record (2026-09-28).** This is the design as it was planned that day. Parts are superseded: the
> third-party DRAW2 detector it mentions was replaced by Duel Lens's own card detector and removed from the
> repository, and click to scan, official card images and Genesys points came later. For how Duel Lens works now,
> see [README.md](../../../README.md) and [docs/DEVELOPMENT.md](../../DEVELOPMENT.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Chrome MV3 extension. The user presses Alt+Shift+Y, draws a box around a Yu-Gi-Oh! card on any page (YouTube first), and sees the matched card's image and full text in a popover beside the box. The side panel keeps the session history.

**Architecture:**
- The background service worker captures the tab and routes messages.
- The content script shows a frozen-frame selection layer and the popover, in a top-layer closed shadow root.
- An offscreen document finds the card, crops the artwork, embeds it with ONNX Runtime Web, and searches a bundled int8 index of about 15k artworks.
- Node tools build that index from YGOPRODeck artwork crops, using the same shared preprocessing and embedding code (`src/shared/`).

**Tech Stack:** TypeScript 7, esbuild (`build.mjs`), Preact 10, Vitest 5 (happy-dom for UI), ONNX Runtime Web/Node 1.30, OpenCV.js (`@techstark/opencv-js`), sharp (tools), `@anthropic-ai/sdk` (opt-in AI check), fake-indexeddb (tests).

**Spec:** `docs/superpowers/specs/2026-09-28-duel-lens-design.md` (read it first). Design mockups: https://claude.ai/artifact/GyYh8rePhF38biGVKLz3cP

## Global Constraints

**Repository and process**
- **Commits:** do not `git commit`; the user has not asked for commits. The lead stages work with `git add`.
- **Ownership:** only edit files in the paths your stream owns (table below). If you need a change elsewhere (a dependency, the manifest, `build.mjs`, another stream's file), stop and report it in your final summary. Do not run `npm install`.
- **Existing contracts** in `src/shared/` must be used, not re-declared:
  - `types.ts`, `messages.ts`, `preprocess.ts`, `embed-core.ts`, `index-format.ts`, `search.ts`, `cards.ts` belong to the lead.
  - `models.ts` belongs to stream A and `names.ts` to stream D.
  - `card-layout.ts` belongs to stream B.
- **Tests:** TDD with Vitest. Test files sit next to the code as `*.test.ts(x)`. UI tests start with `// @vitest-environment happy-dom`.
  - Run only your own tests, e.g. `npx vitest run src/offscreen`.
  - `npx tsc --noEmit` must show no errors in your files.
- **Build:** do not run `node build.mjs`; the lead builds `dist/`. For a visual check of UI, bundle a demo page into a temporary directory under `test/demo-out/` (gitignored by your own `.gitignore` entry request) or the OS temp dir.

**Runtime and platform**
- No code is ever loaded from a CDN at runtime. Models, ORT `.wasm`/`.mjs` (copied to `dist/ort/`), OpenCV.js and fonts are bundled.
- Data-source etiquette:
  - YGOPRODeck: at most 8 requests per second in the tools. Download data and images once and store them locally.
  - Yugipedia: at most 1 request per second, with a descriptive User-Agent that includes "DuelLens/0.1 (personal project)".
- Permissions are fixed by `extension/manifest.json`. Scans only happen after a user gesture (`activeTab`).
- Minimum Chrome version: 124.
- **Message rule:** only the background answers `ToBackground` messages. Other pages ignore messages not addressed to them and never call `sendResponse` for them.

**UI copy and style**
- Copy is plain and specific: "Couldn't match this. Frame the whole card, or just its artwork.", "Face-down card: nothing to read yet.", "Duel Lens can't read this page."
- Visual style follows the design study: a dark overlay (`#17151E`/`rgba(21,19,28,.97)`), gold accent `#E7B955`, a foil gradient on the top edge, and serif card text.

## Review Focus

1. **YouTube keyboard shortcuts:** while the popover is open, `K`, `C`, `←` and `→` are handled by Duel Lens. They must not reach YouTube: K would toggle playback, C captions and the arrows would seek. `Esc` closes the popover. When it is closed, all keys pass through untouched. (Test in C4.)
2. **Card orientation:** the opponent's cards are upside down, and defense-position cards are sideways. The engine must match 180° and 90° rotated crops. (Test in B3.)
3. **Crop mapping:** on HiDPI screens (devicePixelRatio 2), with page zoom, or over letterboxed video (object-fit: contain with black bars), the crop must contain exactly what the user boxed. (Tests in C1 and C3.)
4. **Unreadable pixels:**
   - A restricted page (chrome://, the Web Store) must give "Duel Lens can't read this page" rather than a silent failure. (Test in D3.)
   - A DRM black frame or all-black crop must give "nothing found", never a confident wrong card. (Test in B3.)
5. **Extreme sizes:** a 20×30 px card or a 3000×2000 px fullscreen box must not throw. Tiny crops are upscaled; huge ones are downscaled before detection. (Test in B3.)

## Stream A — Data & index (`tools/`)

### Task A1: Card data snapshot

**Files:** Create `tools/fetch-cards.ts`, `tools/lib/http.ts` (polite fetch with retry and a rate limiter), `tools/lib/http.test.ts`. Output goes to `data/raw/cardinfo.json` and `extension/data/cards.json`.

**Interfaces:**
- Consumes: `trimCard` (`src/shared/cards.ts`).
- Produces: `extension/data/cards.json` = `{ dbVersion, updatedAt, cards: CardRecord[] }`, sorted by id. Also `tools/lib/http.ts`: `politeFetch(url, opts?: {retries?: number}) → Promise<Response>` and `createRateLimiter(perSecond) → () => Promise<void>`.

- [ ] Write a test for `createRateLimiter(4)`: 8 awaited calls take ≥ 1.5 s with fake timers; the first call resolves immediately.
- [ ] Write a test for `politeFetch`: it retries a 429 or 5xx response with backoff (inject a fake `fetch`), gives up after `retries`, and sends a `User-Agent: DuelLens/0.1 (personal project)` header.
- [ ] Implement both, and run the tests.
- [ ] Implement `fetch-cards.ts`:
  1. GET `https://db.ygoprodeck.com/api/v7/checkDBVer.php` to get `database_version`.
  2. GET `https://db.ygoprodeck.com/api/v7/cardinfo.php?misc=yes` into `data/raw/cardinfo.json`, reusing the file if its `dbVersion` matches.
  3. Map every card with `trimCard` and write `extension/data/cards.json`. Log the count and byte size.
  4. If the network is down, fall back to `data/raw/cardinfo.nomisc.json` (already present, no `konamiId`).
- [ ] Run `npx tsx tools/fetch-cards.ts`. Expect about 14,590 cards and a file under 15 MB.

### Task A2: Artwork crops

- [ ] Test `listArtworks(cards: CardRecord[]) → {imageId, cardId, url}[]`:

- [ ] Run it in the background. Expect about 14.7k files, roughly 1–1.5 GB, in about 30–40 min. Continue with A3 meanwhile.

### Task A3: Candidate models

**Files:** Create `tools/fetch-models.ts` and `tools/lib/ort-node.ts`. Modify `src/shared/models.ts`.

**Interfaces:**
- Produces: `createNodeEmbedder(spec) → { embed(images: RGBAImage[]) → Promise<Float32Array[]> }`, built on onnxruntime-node and `embedImages`.
- Produces: `MODELS` entries whose input and output names, pooling, `inputSize`, mean/std and `maxBatch` were verified by loading each model with onnxruntime-node and inspecting `session.inputNames`, `session.outputNames` and output dims.

- [ ] Download `sourceUrl` into `extension/models/<file>` for each candidate. Start with:
  - `dinov2-small`, already registered.
  - MobileCLIP-S0 vision (`Xenova/mobileclip_s0`, `onnx/vision_model_quantized.onnx`). Check its `preprocessor_config.json` for size and mean/std.
  - A small CNN: search Hugging Face for an ONNX MobileNetV3 or EfficientNet-B0 feature extractor. If none can be used, export `timm/mobilenetv3_large_100` with a temporary Python venv in `data/venv`, and delete the venv afterwards.
  - Stay within about 100 MB of models in total.
- [ ] For each model, write a test (`tools/lib/ort-node.test.ts`, skipped when the file is missing) that embeds one real artwork and checks the vector length equals `spec.dim` and its norm is ≈ 1.
- [ ] Check batching: run with batch 2. If it fails, set `maxBatch: 1`.

### Task A4: Build the index

**Files:** Create `tools/build-index.ts` and `tools/lib/index-builder.ts`, with a test `tools/lib/index-builder.test.ts`.

- [ ] Test `buildIndexArtefacts(entries, vectors: Float32Array[], meta) → { bin: Uint8Array, metaJson: string }`:
  - Vectors are int8-quantised.
  - The result survives a round trip through `decodeIndex`.
  - Entry order matches vector order.
- [ ] Implement it, and `build-index.ts --model <id>` which:
  1. Decodes each `data/artworks/*.jpg` with sharp into raw RGBA.
  2. Embeds in batches with `createNodeEmbedder`.
  3. Writes `extension/data/index-<id>.bin` and `.meta.json`, including `dbVersion` from `cards.json`.
  4. Also embeds the card back as `cardId: -1` if `data/card-back.jpg` exists. Get that file once from Yugipedia (the art-box region of `File:Back-EN.png`, using the proportions from `src/shared/card-layout.ts` once stream B has published them; until then, skip it).
- [ ] Build an index for every candidate model. It should take about 10 min per model on the M4 Pro.

### Task A5: Benchmark, model choice and thresholds

**Files:** Create `tools/benchmark.ts`, `tools/lib/degrade.ts` and `tools/lib/degrade.test.ts`. Modify `src/shared/models.ts` (`thresholds`, `DEFAULT_MODEL_ID`).

- [ ] Test `degrade(img, level, seed) → RGBAImage`:
  - It is deterministic for a given seed.
  - The `'clean'` level returns the input.
  - The `'video'` level returns an image of the same size as the input, but with different pixels.
- [ ] Implement the degradation levels with sharp and raw pixel operations:
  - `clean`
  - `mild`: shift and crop 3%, JPEG 70, brightness ±10%.
  - `video`:
    - downscale the card to 64–128 px wide and back up
    - Gaussian blur σ 0.6–1.5
    - JPEG 25–45
    - ±6° rotation with 5–10% misframing
    - colour jitter ±20%
    - a glare blob at α 0.25–0.5 with probability 0.5
  - `extreme`: 40–64 px wide, JPEG 15, blur σ 2.
- [ ] `benchmark.ts --models a,b,c --n 1000 --seed 1`:
  - Sample N artworks, degrade each at every level, embed, and search the model's full index.
  - Report top-1 and top-5 accuracy per level and per model, plus the median ms per embedding.
  - Write `data/bench/report-<date>.json` and a Markdown table to stdout.
- [ ] Calibrate each model's thresholds on the `video` level:
  - `floor`: the 2nd percentile of correct top-1 scores.
  - `score` and `margin`: the smallest values that give at least 97% precision on "confident" answers.
  - Write them into `MODELS`.
- [ ] Set `DEFAULT_MODEL_ID` to the model with the best `video` top-5 whose model file is ≤ 30 MB and whose median embed time is ≤ 80 ms. Break ties on top-1.
- [ ] Accept a real test set (`--real path.json` in the Options export format: `[{dataUrl, cardId}]`) and report it separately.
- [ ] Final report: the table, the chosen model, and whether the spec's success criteria 1 and 2 are met.

## Stream B — Recognition engine (`src/offscreen/`)

### Task B1: Card layout and crop hypotheses

**Files:** Create `src/shared/card-layout.ts`, `src/offscreen/hypotheses.ts` and `src/offscreen/hypotheses.test.ts`.

**Interfaces:**
- Produces:
  - `CARD_ASPECT = 59/86`.
  - `ART_BOX = {x, y, w, h}` for standard cards, as fractions of the full card.
  - `ART_BOX_PENDULUM` likewise.
  - `interface Hypothesis { id: 'quad'|'whole'|'whole-pendulum'|'art'; rotation: Rotation; image: RGBAImage }`.
  - `buildHypotheses(selection: RGBAImage, warpedCard?: RGBAImage | null) → Hypothesis[]`.

- [ ] Measure `ART_BOX` and `ART_BOX_PENDULUM`:
  - Download about 6 full images (`cards/<id>.jpg`, 813×1185) and their `cards_cropped` versions: normal, effect, spell, trap, link and pendulum. Use a scratch script in `tools/` only if stream A agrees; otherwise keep it in `src/offscreen/__measure__/`.
  - Locate each crop inside its full image by a sum-of-squared-differences search on 1/4-scale images, then refine at full scale.
  - Record the fractions to three decimals in `card-layout.ts`, with a comment giving the source and date.
- [ ] Test `buildHypotheses`:
  - With `warpedCard`: it includes `quad` at 0° and 180°, and each image is the art box of the warped card.
  - With a card-shaped selection (aspect within ±0.12 of `CARD_ASPECT`): it includes `whole` and `whole-pendulum` at 0° and 180°.
  - With a squarish selection: it includes `art` (centre square) at 0° and 180°.
  - A landscape card-shaped selection (defense position) is rotated 90° cw and ccw before the `whole` crops.
  - It never returns an empty image.
- [ ] Implement it and run the tests.

### Task B2: Card detection (OpenCV.js)

**Files:** Create `src/offscreen/detect.ts` and `src/offscreen/detect.test.ts`.

**Interfaces:**
- Produces: `loadCv() → Promise<CV>`, which lazy-loads and initialises OpenCV.js once.
- Produces: `detectCard(img: RGBAImage) → Promise<{ card: RGBAImage /* 590×860 portrait */, corners: [number, number][], landscape: boolean } | null>`.

- [ ] Test with synthetic images drawn in the test (plain typed arrays, no canvas):
  - A 400×300 dark background with a 150×219 lighter card-like rectangle rotated 8°. `detectCard` returns a 590×860 card whose centre pixel is the card colour.
  - The same rectangle rotated 90° (landscape) returns `landscape: true` and is still warped to portrait.
  - Pure noise returns `null`.
- [ ] Implement:
  1. Downscale so the long side is ≤ 800 px.
  2. Grayscale → Gaussian blur → Canny with automatic thresholds (median ± 33%) → dilate.
  3. `findContours` (RETR_LIST) → `approxPolyDP` at 2% of the perimeter.
  4. Keep convex quads with area ≥ 15% of the image and a `minAreaRect` aspect ratio within 0.686 ± 0.12 (or its inverse).
  5. Pick the largest, order its corners, and `warpPerspective` to 590×860.
  6. Always free `cv.Mat` objects (try/finally).
- [ ] Make sure OpenCV loads under Node (Vitest) and in the offscreen document. If `@techstark/opencv-js` needs special init (`cv.onRuntimeInitialized` or a promise), wrap it in `loadCv()`.

### Task B3: Engine

**Files:** Create `src/offscreen/engine.ts` and `src/offscreen/engine.test.ts`.

**Interfaces:**
- Consumes: `buildHypotheses`, `detectCard`, `topKByCard`, `mergeCandidates`, `decide`, `getModel`.
- Produces:
  - `interface Embedder { modelId: string; embed(images: RGBAImage[]): Promise<Float32Array[]> }`.
  - `createEngine(deps: { embedder: Embedder; index: LoadedIndex; spec: EmbeddingModelSpec; detect?: typeof detectCard }) → { recognize(img: RGBAImage): Promise<RecognitionResult> }`.

- [ ] Write tests with a fake embedder whose vectors are derived from mean colour per quadrant, and a tiny in-memory index of 4 artworks built with the same fake:
  - A crop equal to artwork #2 gives top candidate #2, `confident: true`.
  - The same crop rotated 180° still gives #2, with `best.rotation === 180`.
  - A landscape crop (rotated 90°) still gives #2.
  - An all-black 300×400 crop gives `candidates` below the floor, `confident: false`, and must not report a confident match.
  - A 20×30 crop and a 3000×2000 crop both resolve without throwing. The big one is downscaled to a long side ≤ 1600 before detection.
  - When the card-back entry (cardId −1) wins, `faceDown: true`.
  - `timings` has `detect`, `embed`, `search` and `total`.
- [ ] Implement `recognize`:
  1. Clamp size (long side ≤ 1600).
  2. `detectCard`, then `buildHypotheses`, then one `embed` call for all hypotheses.
  3. `topKByCard(v, index, 10)` per hypothesis, then `mergeCandidates(…, 10)`.
  4. `decide`, set `best` from the winning hypothesis, and set `faceDown`.
  5. On a thrown error, return `{candidates: [], confident: false, faceDown: false, error}`.
- [ ] Integration test (`engine.int.test.ts`): skip unless `extension/models/<file>` and `extension/data/index-<id>.*` exist. Use `onnxruntime-node` with `embedImages`, and embed 20 real artworks from `data/artworks` with the `video` degradation from `tools/lib/degrade.ts` (once A5 exists). Expect top-5 accuracy ≥ 80%.

### Task B4: Offscreen entry

**Files:** Create `src/offscreen/index.ts`, `src/offscreen/web-embedder.ts`, `src/offscreen/decode.ts` and `src/offscreen/decode.test.ts`.

**Interfaces:**
- Consumes: `ToOffscreen` and `OffscreenRecognizeResponse` from `messages.ts`.
- Produces:
  - `decodeDataUrl(dataUrl) → Promise<RGBAImage>` (via `createImageBitmap` and `OffscreenCanvas`).
  - `createWebEmbedder(spec) → Promise<Embedder>`, which uses onnxruntime-web:
    - `wasmPaths = chrome.runtime.getURL('ort/')`
    - execution providers `['webgpu', 'wasm']`, falling back to `['wasm']` if WebGPU fails
    - `numThreads = crossOriginIsolated ? min(4, hardwareConcurrency) : 1`
    - the model from `chrome.runtime.getURL('models/' + spec.file)`

- [ ] Test `decodeDataUrl` in happy-dom with a stubbed `createImageBitmap` and `OffscreenCanvas`: it passes through the width, height and pixel data.
- [ ] Implement `index.ts`:
  - `chrome.runtime.onMessage` listens only for `isToOffscreen(msg)`.
  - `warmup` loads the model, index and OpenCV once, as one shared promise.
  - `recognize` awaits the warm-up, then decodes and recognises, and responds with `{ result }` (return `true` for an async response).
  - Load failures come back as `result.error` with a readable message.
- [ ] Log timings with `console.debug('[DuelLens]', …)`.
